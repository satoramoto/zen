# Design OS: decisions

Decisions made without asking, for the owner to veto. Newest last. Each says what was decided and why.

> Entries before 2026-10-13 that name `src/library/visuals/`, `@satoramoto/zen/visuals`, `splitStyles` or `lib/visuals.css` describe zen as it was then: visual[flow]'s UI has since moved to openflowfm/visuals (`app/src/ui/`).

## 2026-10-12

1. **Materials replace Chrome.** Parts declare a role (`well`, `screen`, `key`, `handle`, lit); a material set says how each role looks. No Forms facet yet (#27).
2. **Faces + Scale.** Type sizes, the spacing unit and control height move together in one Scale facet, so text and controls grow as one.
3. **Every palette has light and dark.** The scope follows `prefers-color-scheme`, with a Mode override. Missing modes were derived from each source's own colours and marked `// added` (Refero has Elektron, Linear and Ableton in one mode only).
4. **Generic role slots.** The contract has `--role-1`/`--role-2`; Yahaha maps them to `--style`/`--transport` (`yahaha/tokens.css`). Key faces are the instrument extension (`--key-white`, `--key-black`).
5. **Hardware materials and the classic palette/faces** come from Yahaha's pre-minimalism UI (ryangavin/yahaha@0dd53b6), as the `yahaha-classic` pack.
6. **Material shadows are never `none`** (`0 0 0 0 transparent` instead), so components can list them with their own state rings in one box-shadow.
7. **Layouts live outside design systems.** One set of layout primitives (`src/library/layout/`): `Screen` (fixed header and footer, a named grid), `Region` (tabbed views folded in), `Group`, `Tabs`, `Layer`/`Opaque`/`Hole`. Layout systems later (#28).
8. **Tabs are drawn by the materials** (`tabs`: track, tab, chosen, ink, spacing), and the region header has its own inset and rule (`plate.head`): underlines for Push and Ableton, filled for Elektron, segmented for Linear, a hardware selector for hardware.
9. **Layers: a depth stack in the contract** (`ground`, `base`, `raised`, `float`, `overlay`, `top`), each with fill, an opaque `solid`, texture, backdrop, cast and edge, plus one `light` angle per system. The old `plate` and `float` materials became the `base` and `float` layers; `plate` keeps only region spacing. `Opaque` makes every layer inside solid (for panels over a native view); `Hole` is a cut-out.
10. **The Stage's regions are `Region`s on a `Screen`:** AppBar in the header; the keys and status line in the footer; the banks' page tabs are Region views; the mixer's layers are `Tabs` in the aside.
11. **Storybook nests by title** (Field guide, Design OS, Yahaha, open[flow]); composing other repos' Storybooks with refs comes later (#29).
12. **Distribution:** apps consume zen as an npm package, via a GitHub dependency until it's published.
14. **Package `@satoramoto/zen`:** `npm run build:lib` (Vite library mode to `lib/index.js` and one `lib/zen.css`, plus declarations), run on `prepare` so a GitHub install builds it. React is a peer dependency (^19), so an app never gets a second copy. The contract's `Layer` type is exported as `LayerStyle`, because the layout `Layer` component takes the name.
15. **Layer values:**
    - Flat sets read depth as tone steps: `raised` is one surface step above `base`, so FaderBank's Master plate now shows. `overlay` and `top` are `surface-3` with a strong hairline and growing shadows.
    - Hardware keeps its float drop, with bigger casts for `overlay` and `top`.
    - Shadows are written for a light from above; they aren't computed from `light` with CSS trig.
16. **The glass system (`visuals` pack):**
    - The `frost` palette's stem and deck colours are pushed apart in chroma to meet the 0.12 distance rule. `--primary` is both accent and action, and signal green is success.
    - The light mode is all `// added`.
    - The `roomy` scale has a 4px unit and 30px controls; visuals' 40px rows can't be expressed in a scale.
    - `instrument` faces use a system mono instead of loading Recursive. Components set tabular figures themselves.
    - Region spacing is a literal 22px inset and 32px gap, so it holds under any scale.
    - Storybook paints a stand-in desktop behind translucent grounds (`pack.desktop`).
17. **Core and Music components (out of Yahaha):**
    - A hue slot is the number 1–4 everywhere. Role values are `'role-1'` and `'role-2'`.
    - Pad takes a separate `hue` and `role`, instead of part families and a `transport` flag.
    - Keys zones are a generic left and right, with the names passed in as props.
    - Yahaha maps its parts in its own callers (`PART_HUE_INDEX`).
    - Older values stay on Button, StatusDot and BarBeat for now: `t`, `t2`, `m`, `a`, `ok`, `rec`, `lamp` and the deprecated section values.
    - The moved components keep their `yh-` class prefix for now; renaming it is a follow-up.
18. **AppBar's pages are tablists** (two layout `Tabs`, "Display pages" and "Full pages") instead of buttons with `aria-current`. `Tabs.value` may be `null`, which leaves no tab chosen.
19. **Display's and SongForm's roots are plain elements,** so the Stage's Regions carry the names: "Hero", "Transport" and "Song form", or "Song form and transport" in the split layout.
13. **visual[flow] is rebuilt in zen** (`src/library/visuals/`) on the glass system, checked against the original Storybook for drift; the app itself is then wired to zen on a branch in openflowfm/visuals, opened as a draft PR without auto-merge, because that repo is mid-1.0 with its own decision log (#105).
20. **Package entry `@satoramoto/zen/visuals`** (`lib/visuals.js`, `lib/visuals.css`): `VisualsApp`, `setBridge`, `currentBridge`, `Bridge` and the other ipc types. Library code both entries share is one chunk, and a build plugin keeps every library stylesheet in `zen.css` (the build fails if one lands in `visuals.css`), so an app imports both stylesheets.
21. **`VisualsApp`** ports the original's `App` and `main.tsx` setup: a ThemeScope on the `visuals` pack (`frame`, default on), `startChrome` only when the bridge's window label is `main`, and the original's "no app behind this page" note when no bridge is installed. An `editor` view falls back to Home (no Lab).
22. **Export renames for clashes:** ActionButton's `ButtonFace` is `ActionButtonFace` and Param's `format` is `formatParam`; Param's generic `clamp` and `span` aren't exported.
23. **The old generic demo is gone** (`components/index.tsx`, `ArrangerStage`). The Theme inspector moved to `src/library/inspector/` with a local panel and `Group`s; stories that used the demo now use core `Button`, `LampButton`, `StatusDot`, layout `Tabs` and music readouts.
24. **Contract tests run per mode:** every rule (distance, AA, keys, hues, every variable filled) runs over both modes of every palette and pack. The no-literal-radius rule allows `0`/`0px` and `inherit` (BarBeat, TempoReadout and ChordReadout drop their window on a screen; Display inherits), since neither is a radius a theme chooses.
25. **CI builds the package** (`npm run build:lib` in `checks`).
26. **Tiers** (`docs/tiers.md`): every decision belongs to one tier: tokens, primitives, controls, groups, regions, screens, app. Each tier builds only from the one below.
27. **Primitives** (`src/library/primitives/`):
    - `Text`'s `role` is the type role and replaces the ARIA `role` attribute. `code` is the mono face at `--size-body`, since the scale has no code size. Numerals and code are tabular.
    - The tone colours live on one shared `.lib-tone` class, which `Icon` uses too. `on-solid` reads `--action-text`.
    - `Surface` paints one box-shadow list from five slots: border, material shadow, glow, edge, cast. With both a `layer` and a `material`, the material paints the face and the layer adds its backdrop, edge and cast. The default `radius` is `card` for a layer alone, otherwise `control`.
    - The rings are classes (`focusRing`, `pressRing`). The press ring is an inset outline, so it never fights a Surface's shadow.
    - `Step` is 0–6, where N is `var(--space-N)`.
28. **`Stack` lives in `layout/`**, beside `Group`: `tiers.md` puts it in the Groups tier, even though the brief listed it with the primitives.
    - `Group`'s body is a `Stack` with a default gap of 2, as before. `Region` takes a body `gap`, which defaults to none.
    - Stack's step rules are wrapped in `:where()`, so the existing `.x > .lib-group__body { gap }` overrides still win.
29. **The tier checks** (`src/library/tiers.ts`, `tiers.test.ts`, `npm run tiers`) count breaches per widget folder (`components/core/<Name>`, `yahaha/<Name>`, `visuals/<Name>`, `layout`, `primitives`):
    - Pixels: `0`, `1px` and `2px` are allowed, and so are media and container query preludes (variables can't go there). TSX counts px strings and bare numbers on length keys in `style={{}}`.
    - Margins: only on a control's root block (one compound selector, no `__`). Resets to zero pass.
    - Painting: `layout/Group|Stack|Screen.css` count in full. In `Region.css`, only rules other than the plate (`.lib-region`, `.lib-region__head`) count. `Layer.css` (a primitive) and `Tabs.css` (a control) are exempt. App CSS counts only in rules that name a layout primitive's class or `data-part`.
    - Knobs: `--yh-*`/`--vs-*` names declared in CSS and missing from a sibling TSX's **Tuning knobs** list (a trailing `*` lists a family). A CSS file with no TSX beside it may list its knobs in its own comments.
    - A count below its baseline passes: the baseline is a shared file, and forcing every lane to rewrite it would make them conflict. Lower it with `npm run tiers -- --write`. A folder that isn't in the baseline is held to zero.
30. **The burn-down reached zero everywhere** (433 pixel values, 2 margins, 1 painting, 245 undeclared knobs), and the baseline is now all zero, so every rule is an error in every folder. Much of it is translation, not adoption: pixel values became scale-step arithmetic (`calc(var(--space-2) * 55)`) and knobs became declared knobs. `Text` was adopted almost nowhere, and `Surface` only where it kept the look. The next round fixes the primitives so they become the short way: `Text` needs tight line-heights or a size that follows a knob, and `Surface` needs `ref`/`type` and a circle radius.
31. **Lit glow:** materials give `lit.radius` and `lit.strength`. `library.css` builds `--mat-lit-glow` on every element (`SCOPE_VARS`), because a glow declared on the scope resolved `var(--lit)` there, where no lamp colour exists, and every glow was empty.
32. **`Region fit="content"`** sizes a region to its head plus its body (rows `auto auto`, min-content floors). The Knobs region uses it, and the Stage's knobs row is `min-content`. The knobs had collapsed to 0px and drawn over the pads since the Stage moved onto `Screen`. At 1217×752 the Stage now zooms to 0.848 instead of 0.893, because the knobs take their real height.
33. **visuals' proposed tokens stay as declared knobs for now:** row, titlebar, sidebar, inspector, tile and window radius are app-frame sizes, which belong with layout systems (#28). A "measure" (text width) step and an 11px "small" size are Scale candidates (follow-up).
34. **`Text` refinements:** `leading` (`tight` 1, `snug` 1.15, `normal` the face's own, `none` 0; omitted is the role's), `size` (another role's size, or `inherit` = 1em), `weight` (one of the four contract weights), `case` (`upper`, `label`, `none`), and `tabular={false}` for normal figures. They render as namespaced `data-text-*` attributes, because controls already use `data-size` on their roots. `ariaRole` carries the ARIA role, since `role` is the type role.
35. **Text knobs:** `--text-size`, `--text-weight`, `--text-leading` and `--text-tracking` win over the role's value. Each is reset to `initial` on every Text, so a knob set on an ancestor never reaches a nested Text: it goes on the Text element's own class. There's no case or figures knob (those are props), because `text-transform` and `font-variant-numeric` are only declared when a role or prop asks for them, so a Text without them still inherits.
36. **`:where()` everywhere in `Text.css` and `Surface.css`,** tone rules included, so a component's class on the same element refines a primitive without `!important`. `Text` and `Surface` take every native attribute (`AllHTMLAttributes`) and a `ref` (React 19 passes `ref` as a prop; it's typed `Ref<any>`, since the element is whatever `as` names). `Surface` gained `radius="circle"` (`50%`).
37. **Tier rule `type`** (`components`, `layout`, `yahaha`, `visuals`): `font`, `font-size`, `font-weight`, `line-height`, `letter-spacing`, `text-transform`, `font-variant-numeric` in CSS and in `style={{}}` keys. A bare CSS-wide keyword (`font: inherit`, `line-height: inherit`) is a reset and passes. Setting a Text knob doesn't count. Stories are not scanned. The baseline was 802 (components 290, layout 12, yahaha 103, visuals 397). It's now 0 everywhere and locked.
38. **The burn-down moved text onto Text:** 78 of 90 component folders render `Text` (2 before) and 7 render `Surface` (1 before). About 250 knob settings remain where the scale has no matching prop: sizes off the role steps (visuals' `--vs-text-*` ramp, em ratios, `calc` sizes), leadings 1.25/1.3/1.45/1.5 or `var(--control-h)`, weight 500/700, and tracking 0. Those are honest leftovers. A `leading` step for 1.25–1.5 and a weight-medium token would retire most of them (follow-up).
39. **visuals' control reset** `.vs-root :where(button, select, input, textarea) { font: inherit }` now skips `.lib-text`: it had class specificity and silently erased every Text button's role inside the visuals app. `.vs-root .vs-num` sets only the readout face and word spacing, and each `vs-num` element sets `tabular` itself.
40. **Radio's root is a body Text** like Checkbox's, since they share `.lib-check`'s type knobs. Segmented and Select pass their hooks' ARIA `role` through `ariaRole`. The visuals view switch writes its words capitalised in code instead of `text-transform: capitalize` on Segmented's part.
41. **Surface adoption only where it's the same paint:** the Slider track and thumbs, the Switch thumb, the Meter channel, Knob's well and cap, ChordReadout's screen, and CrashPrompt's report. Faces with a tint layer over the key material (Button, Toggle key, Select trigger, the Switch track, ActionButton) keep their own painting, because a Surface can't layer a tint yet (follow-up: a `--lib-surface-tint` slot).
42. **The lab editor moves into zen** (`visuals/Editor/`, `StageGraph/`, `StageInspector/`, and the model's `stages`, `editor`, `stage-layout`, `lab`), so openflowfm/visuals can drop `@openflow/widgets` (`docs/widgets-in-visuals.md` is the review). The editor's inspector is `StageInspector`, since `visuals/Inspector/` is the home's.
43. **The lab is its own package entry, `@satoramoto/zen/visuals/lab`** (`lib/visuals-lab.js`, `lib/visuals-lab.css`), not part of `./visuals`: the app's CI fails when `apply`, `set_value`, `previews` or `default_shader` reach its non-lab page, and a bundler never splits one module across chunks, so anything the lab shares with the app would carry them in. For the same reason the lab's commands and its stage-picture poll live in `model/lab.ts` (duplicating `api.ts`'s five editor commands rather than calling them). `splitStyles` now sorts each chunk's stylesheet by where its sources live (a chunk mixing library and visuals styles fails the build).
44. **`VisualsApp lab={VisualsEditor}`** mounts the editor for the `editor` view and starts there; every header's switch offers it through a `ViewList` context (zen's built package can't read the app's `VITE_LAB`). Leaving live mode still goes to the home, not back to the editor (follow-up).
45. **Core `Graph` (with `Port`) and `Device`** replace the widgets' `chrome/Graph`, `Port`, `Device`, `DevicePortRow`, with the same ownership bargain (the host owns positions and cords, the graph its view). New: `GraphView.fit(max?)` and `fitOnResize`, so a host fits the graph instead of shrinking faces. Left out of Device: fold, power, hot-swap, the chooser band and reserved rows.
46. **Stage kinds are told apart by tone, not hue**: in the visuals pack every hue already means something (green signal, amber caution, hues the stems), so a node's leading mark and its cords use text tone steps; a problem is `--danger`.
47. **Node widths are knobs in scale steps** (`--vs-stage-wide` 168px, `--vs-stage-narrow` 88px under `roomy`); the graph's layout positions are in graph units from `stage-layout.ts`, so under another scale they drift apart (follow-up: read the widths from one place).
48. **Self-assembling layout** (`docs/assembly.md`, `layout/assembly/`). Needs are declared in scale units (`control`, `target`, `space`, `unit`, `lines`, `chars`, and hairline `px`), never measured. The solver resolves them from the facets: the scale for sizes and the materials' plate for inset, head and gap. It reads the materials' CSS lengths with a small parser that throws on anything it can't read. `ROLE_LEADING` copies Text.css's leadings, and a test holds the two together. `chars` uses an average glyph width of 0.6 em.
49. **The solver's rules:**
    - The lowest priority steps down first, strictly. Within that tier, a step that shrinks the body wins.
    - Once the body fits, a take-back pass restores any step a later one made unnecessary, highest priority first.
    - Zoom comes only when no step down helps any more. That is usually when everything is at its last form, but a region whose next form isn't smaller where the body overflows isn't stepped for nothing.
    - Spare room goes first to each tier's ideal, then to the growers, highest priority first and in proportion to their ideals. Regions stretch across their row.
    - The header and footer are each region's first form at its ideal height. They never step or zoom.
50. **Density is the fit aim:** `dense` tests each form at its least, `balanced` halfway, `roomy` at its ideal. A roomy pack that runs out of steps retries as dense before zooming.
51. **Ranks:** `now, next, controls, context, chrome` (`RANKS` in the contract), scored 100, 80, 60, 40, 20. A pack may reorder them. "What's playing never shrinks first" is `now` on top.
52. **Every pack's `minTarget` is 24**, WCAG 2.2's target size minimum (`// added`: no source sets one). The zoom floor is `minTarget / control`: 0.857 at the compact scale, so the Stage's current 0.848 at 1217 × 752 would hit the floor once it is assembled. Yahaha is `dense`, visuals `roomy`, and the studio packs `balanced` (`// added`).
53. **Pairs** are two regions in rows of one stack, both first or both last, that take one width. Any other pair throws.
54. **`AssembledScreen` places each slot absolutely.** The rects go in as unitless custom properties (`--lib-at-x` … `-h`), and `Assembly.css` multiplies them by `1px`. The px come from the facets, so this is the screen tier using tokens, not a literal. The body zoom (`zoom`) sits on an inner box, so it never scales the zone's offset. The room is the one thing measured (the screen's own box); where nothing measures, it is 1440 × 900.
55. **`useForm(forms, given?)`** returns the `form` prop if given, else the region's chosen form when it is one of the component's forms, else the first. A region passes the same form id to every declaring component inside it, so a per-part mapping is a follow-up.
56. **`ThemeScope` takes `principles`** and puts its facets and principles in context (`useThemeScope`). The Storybook decorator passes the pack's. Outside a scope, the solver uses the first pack.
57. **Thinner blocks:**
    - `Layer` is a deprecated alias of `<Surface layer radius="card">`. It keeps the `lib-layer` class, because visuals' CSS names it.
    - `Opaque` and `Hole` moved to `primitives/Surface`. Layer.css is gone.
    - `Stack` is a primitive (this reverses 28). The layout index doesn't re-export it, because the library's `export *` of both folders would clash.
    - `Group` is a column `Stack` holding the label and a body `Stack`.
    - The story helper `.lib-stack` in library.css became `.lib-specimens`. It had the Stack component's class name and could outrank Stack's `:where()` gap rules.
58. **visual[flow]'s Home and Stage are assembled screens** (`homeSpec` in `visuals/HomeLayout`, `stageSpec` in `visuals/StageLayout`). Home: sidebar, then a column of header, hero, pane (the grid) and bar, then inspector. Stage: crate, then a column of head, centre (the picture's open middle) and dock, over the preview `Hole`, all in one `Opaque`. Every region is plateless: frost paints no plates, and the screen's 32px gap is the seam.
59. **Where a panel docks is a solver question asked twice.** First `homeDocks` / `crateDocks` run the spec with the panel free to choose (`docked` or `overlaid`, which takes no room). Then the viewer's choice turns that into a mode (`modesFor`, `crateModeFor`, which now take "docks" in place of a width). The screen is then drawn with each panel pinned to its mode's form. So "remembered where it docks" (`prefsAt`, `CRATE_KEY`) is still decidable, and a panel the viewer hid gives its room back to the column.
60. **The breakpoints come out of the needs:**
    - The sidebar docks from 900 and the inspector from 1196 (the original said 1200). The hero (`now`) wants 588px across (`HERO_FORMS`), the original's 600px of column content less our wider seams, and the panels (`context`) go before the column narrows past it.
    - The crate docks from 1100: the centre (`now`) wants 820px open, the original's window less the crate.
    - Live's header and dock rank `chrome`, below the crate, so they shorten first. At 1100 the crate is docked and the dock is compact, as in the original.
61. **Home's ranks:** the hero is `now`; the header and the bar are `controls`; the panels are `context`. The pane's tile size is `chrome`, so the tiles go small (124px) before a panel undocks. "Wide" needs five 150px tiles. So the tiles are small below about 1110px (the original said 1100), and also between 1196 and about 1405 while the inspector is docked, where the original kept them wide.
62. **Overlaid panels:** Home's take a zero-width slot at the window's edge and draw the panel from it, so the panel isn't remounted when it docks or undocks. Live's laid-over crate is drawn outside the assembled screen, so the dock and header keep their 8px inset from the window. The overlay inspector starts under the title bar again, as inspector.css had it (the port had lost this).
63. **The hero paints the whole window's tint** (its 100vmax spread shadow, no longer clipped to a column that no longer exists). The docked panels' cells paint nothing over it; the frost's base layer is `--surface-0`, the same tint. With no hero, the docked cells keep the base plate.
64. **The hero's height is its slot's** (`--vs-hero-cap: 100cqh`; `.vs-lay-hero` is a size container), at most 440px (`full`), or 288–320px (`compact`, in short windows). The original used half the measured column. `useColumnHeight` and `--vs-lay-col-h` are gone.
65. **Component forms replace their queries.** These are now forms:
    - Views' `Header` `full`/`narrow` (was ≤699px, now below 620px).
    - The library search folding under the narrow header.
    - `StageHead` `full`/`short` (≤900px).
    - `StageDock` `full`/`compact`/`stacked` (the 940 and 700 container queries).
    - Home's pane `wide`/`small` (≤1099px: tile size and padding).

    Kept as queries: Hero's 680px words-beside container query (the card's own reflow), Library's and PlaylistHead's ≤899px rules, and the dialogs' and sheets' own narrow rules.
66. **`Form.ratio`: height follows width** (`{ w, h, fixed? }`). The solver places twice: widths never depend on heights, so the second pass gives a ratio form exactly the height its width asks (never below its min), with no growth past it. Width-follows-height is left out.
67. **`Form.parts` and `combineForms`** for a region holding two declaring components (the song form over its transport). `useForm(forms, given, part)` reads `parts[part]`; the placement carries `parts`. Chosen over a `<FormPart>` wrapper, so a component that draws both halves itself (SongForm `part="both"`) reads both.
68. **`ScreenSpec.edge`**: room round the body and footer, the header edge to edge (the Stage's app bar). The Stage uses `--space-2`, down from the old `--space-5` padding: at 900 × 700 the mixer beside two rows of pads needs those px to stay above the zoom floor.
69. **The solver doesn't take a step that makes the body worse on an axis where it then overflows** (one row of sixteen pads is shorter but too wide). When it must zoom, it first takes back every step that cost the body nothing; below the floor it takes back what the floor's room holds (a transport stepped narrower and taller while the hero was still tall) and keeps that only if it then fits; under the zoom it takes back what the zoomed room holds.
70. **The Stage is a spec** (`Stage.spec.ts`): the pair `hero`/`mixer`, priorities from STAGE.md (hero `now`, song form `next`, transport, mixer, knobs and pads `controls`, bar, keys and status `chrome` in fixed zones). `useFit`, the GRID ratios and every hand-tuned size in Stage.css are gone; `split` is a second spec (`STAGE_SPLIT_SPEC`). The keys' px width is the keys slot's width less the plate inset, from the placement (`useScopePrinciples`), not measured.
71. **Forms are truthful, so they are wider than the old hand-tuned floors**: the hero's least is 15.4–17.4 control heights wide (a 7-character section, a 16-character fingering), the mixer's head (page tabs and the five layer tabs) sets FaderBank `short` at 525 px, the knobs' least label fits "METRONOME" in caps, a pad's least side fits its label and its waiting chip. So the solver steps more than the old screen did: at the board the classic pack's mixer is `short`; at 1217 × 752 the hero is `minimal` under classic and elektron. New middle forms fill the gaps: PadBank `small` (no chip; the ring shows waiting) and the transport's `tight` (three rows, no taller than the hero's `minimal`).
72. **visual[flow]'s pack scrolls at the floor on the Stage below the board** (frost's 32 px gaps and 22 px insets). The test pins it as the one expected overflow; the airy scale (40 px controls) on the 900 × 700 screen also hits the floor.
73. **`ScreenSpec.aspect: { ratio, fit? }`** (`fitAspect`). The screen lives in the largest box of that ratio inside the window, centred; the header and footer belong to the screen, so they span the box. The box keeps its exact size (1217 × 684.5625) and its offset is rounded down to whole px, so text isn't drawn on half pixels. The leftover strips are `bands` in the placement, drawn as empty, `aria-hidden` `Surface layer="ground"` elements. The zones now sit in a `data-part="room"` element, which also exists without an aspect, so the DOM is the same either way. `Placement` gains `room`, `bands` and `scale`. A ratio that isn't a positive number throws.
74. **Two fits, `contain` and `scale`.** `contain` (the app) lays the screen out in the box, so a smaller window steps forms down. `scale` (`design: { w, h }`, whose ratio must match) lays it out once at the design room and draws the room with `transform: scale(box.w / design.w)`. A transform rather than `zoom`: hit-testing and `getBoundingClientRect` follow it in every engine, content keeps laying out in design px, it doesn't relayout on resize, and it doesn't compound with the body's last-resort zoom. `cover` and `stretch` are left for later.
75. **The Yahaha Stage is 16:9 and its board is 1920 × 1080.** Both specs use `contain`. A 1440 × 900 window is now a 1440 × 810 room (letterboxed); 2560 × 1080 is the board pillarboxed. The stories default to `fit: 'scale'` (`STAGE_SCALED_SPEC`, the board drawn to fit the canvas) and have a `fit` control. The stories that show stepping (Small, Narrow, Letterboxed, Pillarboxed, SplitSmall) pin `contain` at their size, and `NarrowScaled` shows the same frame scaled.
76. **What 16:9 costs at 900 × 700**: a 900 × 506 room is below the Stage's least at the floor under every pack, so it scrolls there. visual[flow]'s pack also scrolls at 1217 × 752. The placement tests pin both. Every other pack and window is viable.

84. **Ambient light** (owner: "the glass material to react to the preview video"). The app's preview is a native view the page can't blur, so glass reacts to its colour instead, as Apple TV's and YouTube's ambient modes do. The `Ambient` primitive (`primitives/Ambient.tsx`, maths in `Ambient.model.ts`) samples its source (a video, canvas, image, URL or a function returning pixels) into a 16 × 9 canvas at `rate` Hz (10), averages six regions in linear light (`avg`; `left` / `right` the outer quarters; `top` / `bottom` the outer thirds; `centre`), eases them in OKLab with a 600 ms time constant, and writes `--ambient-*` as `oklab()` on its own element, with `--ambient-strength` 0–1 eased up from 0 once it has a picture.
    - The contract declares them (`AMBIENT_VARS`), and `toCssVars` sets neutral fallbacks on the scope (`var(--surface-2)`, strength `0`), so CSS that mixes by strength looks exactly as before with no Ambient or no picture. Because they are in `toCssVars`, the "only contract variables" check accepts them with no change to it.
    - A value built from them must be declared on the element that reads them (as `--mat-lit-glow` is), not in `toCssVars`: a custom property resolves `var()` where it's declared, so on the scope it would only ever see the fallbacks.
    - Under `reduce` (the app's Reduce flashing) or `prefers-reduced-motion`, the time constant is five times longer (at least 3 s) and the rate at most 2 Hz: the light drifts, it never steps.
    - It pauses while the tab is hidden, clamps each step's time so nothing jumps after a pause, keeps the last colours when a cross-origin picture taints the canvas, and halves its rate while a sample costs over 1 ms. It allocates nothing per sample except the 16 × 9 `getImageData` result, which the canvas API can't avoid (a function source avoids it).
85. **Layers take ambient light; frost's glass does** (owner: "I would like the glass material to react to the preview video. Really show off the material system"). Each layer can take `{ fill, edge, cast, lightness: [min, max] }` (`LayerAmbient`): plain shares and an OKLab band, emitted as `--layer-<name>-ambient-*`, default `0%` and `[0, 1]`. They sit in `Materials.ambient` (per layer, optional) rather than on `Layer` itself, because the shared library test reads every `Layer` field as a string. The light is built on each element, never in `toCssVars`, so it reads the nearest `Ambient`:
    - **Scope vars** (library.css, beside `--mat-lit-glow`; `SCOPE_VARS`): `--ambient-light` is the region an element takes (`data-ambient`), inherited; `--ambient-held` is it held to the element's band (`oklch(from … clamp(--ambient-l-min, l, --ambient-l-max) c h)`), which a Surface sets from its layer (`0`..`1` on the scope). The relative colour lives there because primitives' CSS may not name a colour function.
    - **Fill**: `--ambient-held` mixed with transparent at `share × --ambient-strength`, laid over the fill as its own background layer. A layer over the fill rather than a `color-mix()` of the fill itself, because hardware's fills are gradients, which `color-mix()` can't take: it would make every hardware surface transparent. Over an opaque fill the two are the same mix; over a translucent one the alpha comes out the same and only the colour interpolation differs (sRGB compositing rather than OKLab).
    - **Edge**: an inset line on the lit side (`--light-angle`, `--border-width` thick) in the colour at `edge × strength`. **Cast**: a glow (`--space-6 × 2` blur, offset `--space-2` along the light) at `cast × strength`. Both are one more shadow slot, `--lib-surface-ambient-shadow`, between the edge and the cast.
    - **Region**: `<Surface ambient="left">` (and `Layer ambient`) takes `--ambient-left`; surfaces inside inherit it; the default is `avg`. With no `Ambient`, or strength 0, every share is 0: the tint and shadows are transparent, so the surface looks exactly as before. Nothing transitions in CSS: colour moves only as fast as Ambient's easing (and drifts under Reduce flashing).
    - **Frost's shares** (fill / edge / cast): `base` 24% / 0 / 0 and `raised` 20% / 0 / 0 (a tint only: regions have no edge, decision 68); `float` 36% / 60% / 35%; `overlay` 32% / 60% / 30%. `ground` and `top` take none, nor does any other pack.
    - **Contrast is bounded by the band, not only the share.** The colour's OKLab lightness is held at most 0.33 in the dark mode (the page over the lightest HUD, `#3c3c3c`, is about that) and at least 0.87 in the light (the light frost, `#e6e6e6`), via `--scheme-light`. Checked over every in-gamut colour at the band's edge, all hues and chromas, against `--text-3` (`#a4a4ac` dark, `#56565e` light) over the lightest dark HUD and the darkest light frost: dark base 4.88:1 → worst 4.89, raised 4.39 → 4.49 (it only gets better; captions on raised take the lighter step, as before), float 7.10 → 6.32, overlay 7.20 → 6.48; light base 5.99 → 5.54, raised 6.55 → 6.02, float 6.33 → 5.58, overlay 6.35 → 5.66. Even at a 100% share the band keeps 4.75 (dark) and 4.70 (light).
    - The `Design OS/Primitives/Ambient` story is real `Surface layer=…` panels under the visuals pack (left and right panels `ambient="left"` / `"right"`, raised chips inside them inheriting it); its story-only tint control is gone.
